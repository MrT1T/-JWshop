# JWShop — документация для агентов

Этот каталог (`jwshopdoc/`) содержит техническую документацию репозитория **JWShop**,
собранную специально для того, чтобы AI-агенты и разработчики могли быстро
сориентироваться в проекте без необходимости вычитывать весь код с нуля.

Документация описывает **фактическое** состояние кода на момент написания
(2026-07-30), а не намерения или планы — там, где реальность расходится с тем,
что заявлено в старых README, это явно отмечено.

## Что такое JWShop

Учебный/демонстрационный интернет-магазин украшений и часов (jewelry & watch
shop). Состоит из двух независимых пакетов в одном репозитории (не monorepo с
общим package.json, просто два соседних проекта):

- **`client/`** — фронтенд на Next.js (App Router) + Chakra UI. Полностью
  рабочий, со страницами, тестами и промо-баннерами. Это основная часть
  проекта на сегодняшний день.
- **`server/`** — backend-заготовка на Express + TypeScript. Реализован только
  каркас (health-check, CORS, логирование, 404-обработчик). Роуты,
  контроллеры, сервисы и модели, описанные в `server/README.md`, **ещё не
  написаны** — client работает полностью на моковых данных внутри компонентов.

## Быстрый старт для агента

1. Разобраться, в каком пакете задача — `client/` или `server/` — они полностью
   независимы (свои `package.json`, `node_modules`, `tsconfig.json`).
2. Установка зависимостей и запуск — из **своей** папки пакета:
   ```bash
   cd client && npm install && npm run dev   # http://localhost:3000
   cd server && npm install && npm run dev   # http://localhost:4000 (по умолчанию)
   ```
3. Перед изменением кода — прочитать [CONVENTIONS.md](./CONVENTIONS.md) (стиль,
   линтер) и профильный документ ([CLIENT.md](./CLIENT.md) /
   [SERVER.md](./SERVER.md) / [PROMO_BANNERS.md](./PROMO_BANNERS.md)).
4. Клиент и сервер сейчас **не связаны по HTTP** — на страницах клиента везде
   захардкожены моковые данные (массивы `products`, `cartItems` и т. п. прямо в
   `page.tsx`). Не стоит искать fetch-вызовы к `server/` — их нет.
5. При изменении UI-компонентов с текстом/структурой — проверить и при
   необходимости обновить снапшот-тесты (`npm run test:update` в `client/`), см.
   [TESTING.md](./TESTING.md).

## Важные несоответствия документации и кода

- `server/README.md` описывает REST API с CRUD для товаров/пользователей/заказов,
  структуру `src/routes|controllers|services|models|utils` и файл `.env.example`.
  Ничего из этого в репозитории нет — есть только `app.ts`, `index.ts` и
  `middlewares/notFound.ts`. Подробности в [SERVER.md](./SERVER.md).
- `client/README.md` — это нетронутый шаблон от `create-next-app`, не отражает
  реальную структуру проекта (Chakra UI, промо-баннеры, страницы shop/checkout/
  contacts). Актуальное описание — в [CLIENT.md](./CLIENT.md).
